## 工单支持（在线客服）

**是什么**：站内工单系统，用户遇到任何问题都可以在线提交工单，与管理员进行一对一的会话式沟通，全程留痕、可追踪。

**用户侧入口**：登录后进入控制台，侧边栏「**工单支持**」。

- **提交工单**：填写问题标题（5-100 字）、问题分类（综合问题 / 计费账单 / 技术故障 / 功能建议）、优先级（低 / 普通 / 高）、问题描述（5-2000 字）。描述越具体（现象、发生时间、涉及的令牌与模型），处理越快。
- **会话沟通**：工单详情页以会话流水的形式展示全部往来消息，客服回复以醒目样式区分。客服回复后工单状态变为「已回复」。
- **状态流转**：`待处理 → 已回复 →（用户追回 → 待处理）→ 已关闭`。用户随时可以补充信息（追回）或确认问题解决后自行关闭工单。
- **列表视图**：我的工单按「待处理优先、最近更新靠前」排序，状态徽标一目了然。

**管理侧入口**：管理员控制台侧边栏「**工单管理**」。

- 红点徽标实时显示**待处理工单数**（新单 + 用户追回），2 分钟缓存刷新，不拖慢后台渲染。
- 列表支持按 `待处理 / 已回复 / 已关闭 / 全部` 筛选，展示提交人邮箱、分类、优先级与最近更新时间。
- 详情页可直接回复用户、关闭或重开工单（误关单据可由管理员重开回到待处理队列）。

## Coding Plan 双池与转换 API

**是什么**：面向 Coding Plan（Claude Code、Codex、Gemini CLI 等）订阅制账号的两大资源池体系。

- **官方池**：账号来自官方订阅渠道，按厂商聚合展示，支持额度水位、限流状态与账号健康度管理。
- **自建池**：自有账号池，支持导入、分组、tier 档位与独立定价。
- **转换 API**：为每类厂商提供标准化的转换端点，第三方客户端可以像调用原生官方接口一样使用池内账号。

**在哪里**：管理后台「Coding Plan 池」页面统一管理；前台「Coding Plan」页面向用户展示可订阅套餐与时段折扣。

## 官方源同步管线与快照审计

**是什么**：Coding Plan 官方价目与套餐目录的自动同步机制。

- **定时同步**：`pease:sync-official`（每 6 小时，可 `--vendor=xxx` 单家）抓取 15 家厂商官方文档页，**先落快照**（storage 快照 + docs/upstream-snapshots 镜像）再解析比对——快照即审计凭证，失败可回放；
- **校对流水**：与库内目录/价目 diff 出 new/missing/变更，全部进**待确认清单**，绝不自动改库，由管理员在管理端逐条核对后点「应用」（applyCatalog）；
- **大改版判别**：pending 数量多 ≠ 解析故障，先看明细是否官方扩目录（如某日 new 41/missing 15 即官方大改版日）；
- **在售系数比对**：`pease:verify-ratios`（每 6 小时）对 24 家模型折算比率做 stale 检测与定价源 diff（0 stale/0 change/0 failure 为健康基线），异常自动写告警；
- **内置官方定价源**：`GET /api/coding_plan/pricing_source/{code}` 把模板目录发布为约定 JSON，供应商编辑框「使用内置官方源」一键填入，官方改价自动进待确认清单。

**在哪里**：管理后台「Coding Plan 池」→ 同步流水与校对清单卡片。

## 窗口配额与账号冷却熔断

**是什么**：账号池的用量治理与故障隔离。

- **三窗口配额**：每账号独立维护 5 小时滚动 / 自然周 / 自然月用量窗口，`pease:reset-coding-plan` 定时重置，用量阈值（默认 80%）触发展警，单账号可手动重置；
- **冷却熔断**：上游 429/连续失败把账号置冷却态（cooldown_until），到点**自动恢复**参与取用（TestCooldownRecovery 回归保证）；多账号按 priority 顺序取用，坏账号不拖累整体可用性；
- **用量折算审计**：每次调用写 usage_logs，流水 meta 快照记录时段折扣与命中窗口，计费全程可回溯。

**在哪里**：管理后台「Coding Plan 池」→ 账号列表三窗口进度条与状态徽标。

## 智能成本路由与故障自愈

**是什么**：中转层的智能调度能力，同一模型存在多个可用渠道时自动选择最优路径。

- **成本优先**：在满足能力与分组约束的前提下，优先路由到成本更低的渠道，降低整体中转成本。
- **故障自愈**：渠道连续失败会进入**冷却期**（渠道级 `cooldown_until`），冷却期内自动绕行其他渠道；冷却结束自动恢复参与调度，无需人工干预。
- **超时降级**：请求超时自动切换备选渠道，保障可用性。

**在哪里**：管理后台「渠道管理」配置渠道与权重；「全局日志」可观察实际路由路径与失败切换记录。

## 时段折扣与促销体系

**是什么**：Coding Plan 的两层营销定价能力。

- **模型级时段折扣（time_discounts）**：比率行自带时段窗口数组，计费引擎**按调用时刻自动命中折扣**乘入折算量（未配置/未命中=原价，折扣强制 (0,1)），支持 `end<start` **跨零点窗口**（如 22:00→08:00 夜间 5 折），判定统一北京时间口径；流水 meta 快照 `time_discount`/`time_window` 供审计；`pease:coding-plan:test-time-discounts`（28 项断言，事务内零残留）回归自检。
- **促销活动**：满减、折扣、赠金等多种类型，支持预设模板一键创建，到期提醒（PromotionReminder）每日 9 点扫描生成。

**在哪里**：管理后台「Coding Plan 池」→ 模型折算比率（比率行内配置 time_discounts）与「促销活动」卡片；前台「Coding Plan」页向用户展示含折扣的在售套餐。

## 官方源健康告警

**是什么**：对「官方定价同步源」的健康监控与告警机制（P1-9）。定价数据（coding plan 官方价）依赖外部官方页面同步，一旦同步连续失败，会直接影响成本核算与价格准确性。

- **升级判定**：同厂商最近一次流水为失败态时，新的失败会升级告警状态；**成功一次即自动复位**，告警自清除，无需人工干预。
- **可视化**：管理后台「Coding Plan 池」页首「官方源同步健康」卡片——告警时红边框 + 徽标 + 风险行高亮；侧边栏「Coding Plan 池」入口同步显示红点徽标。
- **双写入点覆盖**：定时同步任务（sync-official）与人工校验（verify-ratios）共用同一判定逻辑。

## 管理端可观测与在线自检

**是什么**：内置的管理端自检页面（admin-observability），14 项断言覆盖双池、冷却、成本路由、时段折扣、促销、货币与健康告警等核心链路，部署后可一键在线自检确认环境正确性。

- 本地空库会自动跳过依赖真实数据的断言；生产环境全量生效。
- 配合各功能的专项自检脚本（`tests/*.php`），构成部署验收基线。

## 多币种与汇率结算

**是什么**：支持按用户设置**结算币种**（users.settlement_currency），计费展示与扣费按币种换算；汇率支持手工维护与缓存。

**在哪里**：管理后台「系统设置」维护汇率；用户在控制台「个人信息」选择结算币种。
